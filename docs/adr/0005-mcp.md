# 0005. Workspace testing over MCP

Accepted. The developer’s MCP client edits the host repository and asks a sandbox to execute its tests. The host remains the source of file changes. Sync, test, edit, sync and retest work against a single sandbox until it is destroyed or expires.

## Transport and authority

`sandboxctl mcp` uses the official Go MCP SDK v1.8.0. Its stdio transport handles protocol discovery, negotiation, tool schemas and structured responses across supported protocol versions. Standard output belongs to the protocol and diagnostics use standard error. The MCP dependency and its schema and transport dependencies enter the CLI build. The daemon and public Go SDK have no MCP imports. All daemon operations use the public Go client.

Startup flags identify the host workspace and allowed images. The CLI writes a mode-0600 ownership receipt when it creates a sandbox. The receipt holds a fingerprint of the canonical host workspace, daemon endpoint, credential and allowed image and network sets. A restarted stdio process with the same authority can resume the sandbox before expiry. Sync and destroy lock the receipt across processes. If recording ownership fails, creation removes the container. Confirming expiry or destruction clears the receipt and manifest. Creating a sandbox explicitly requests the offline network. Additional network modes require a startup flag and remain subject to daemon policy. The prebuilt example image supplies test dependencies while disconnected. Every operation on a live sandbox replaces its relative lifetime with the configured TTL.

## Tools and state

Clients that display only MCP text receive execution output and file contents there as well as in the structured result.

The eight tools create and destroy sandboxes, sync workspaces, start, inspect and cancel executions, and read or write guest text files. The client can supply an idempotency key when starting work. After 60 seconds of observation an active command returns its ID. The execution stays available for inspection and cancellation. MCP requests tail retention when starting a command. After output exceeds the shared 1 MiB budget, the daemon keeps recent output, including the terminal diagnostic. The default result contains the last 64 KiB of each retained stream. A clipped result points to offset zero. Subsequent reads page forward from the specified byte offset in each stream. UTF-8 rune boundaries preserve text across pages. A daemon-level truncation remains visible at the end of the available pages.

Sync walks the configured directory through a rooted filesystem handle. It skips symlinks, special files, `.git`, `.venv`, `node_modules`, and `.env`. The root `.gitignore` supports simple basename and rooted globs, directory suffixes, and negations within traversed directories. Nested ignore files and recursive double-star syntax are outside the supported subset. Each regular file has a SHA-256 digest and an executable flag. The serializer preserves executability and gives the sandbox user read access to uploaded files. Sync counts skipped directory trees as single exclusions.

A change set is validated against the archive limits before guest mutation. The manifest in `~/.cache/tiny-sandbox/mcp/<sandbox_id>.json` records both confirmed file versions and pending changes. Atomic replacement and a pending record allow retries after an interrupted deletion or extraction. Deletions run with bounded argv batches of at most 100 relative paths rooted at the guest workspace. The image user creates parent directories so it can delete or replace nested entries. One archive carries all changed files. Reset ignores the previous manifest and reuploads the host files, including after local cache corruption. It can infer deletions only during an incremental sync with a readable manifest. Sandbox edits stay local to the sandbox. Destroying it removes the manifest. The MCP destroy operation requires the purge capability and removes the sandbox from the daemon listing after container cleanup.

## Acceptance

The official SDK command transport drives the compiled CLI against a real daemon and Docker. The transcript includes the failing and passing test in a temporary checkout of the project’s Python SDK, a local source edit, file deletion and exclusion checks, file metadata, output paging, deadline renewal, an offline policy rejection and confirmed container cleanup. Additional cases sync full pinned checkouts of jsonschema-go and the official MCP Go SDK, check the guest copy by SHA-256, cross the 1 MiB output cap, and verify that unsuccessful archive preflights leave the guest unchanged.
