# 0003. SDK retries, execution identity and observation

Accepted. The Go, Python and TypeScript clients share an HTTP contract. A server can accept work or finish a command while the caller is disconnected. The SDKs therefore track what the caller can establish from a response, from a replay, and from a subsequent read.

## Client configuration and discovery

Each client owns its endpoint and credentials. Optional features require authenticated discovery before the first mutation, since older servers can silently ignore new fields. Basic calls work without discovery. A cached advertisement is scoped to the client that fetched it. In Go, waiting for discovery is cancelable, failures leave the cache empty, and an explicit refresh returns a copy so its caller cannot alter the advertised capabilities. The Python E2B adapter checks the active client for each command operation. The TypeScript adapter lets callers abandon a shared discovery without aborting another observer's request.

Stream duration is controlled by the caller. A client-wide HTTP timeout would also terminate healthy long-running streams. The native TypeScript SDK uses Web APIs and accepts a fetch implementation that supports streaming and cancellation. Node environment defaults are optional, so browser imports need no Node globals. Explicit configuration takes priority over the environment. The Go and TypeScript retry settings use zero for the default of three and a negative number to disable retries. The Python client uses zero to disable retries. The E2B facade targets a pinned local compatibility image. ## Retry and recovery

A transport failure describes what the client received. Even a partial write can reach the server. Each operation decides whether replay is safe. The request layer reads the whole response before accepting it so a truncated body remains eligible for recovery. Ordinary retries use jitter between half the backoff cap and the cap to stagger recovering clients. A positive supported Retry-After value overrides that delay. JavaScript splits long waits into intervals within its timer range.

| Operation | Reason for its retry policy |
| --- | --- |
| Sandbox create | A second request can allocate another container. Send once. |
| Relative lifetime update | Replaying later can extend lifetime a second time. Send once. |
| Archive upload | Extraction can partially change files before an acknowledgement is lost. Send once. |
| Managed kill | The first signal may already have terminated the process. A second acknowledgement of “already done” cannot establish who sent the signal. Return the immutable execution identity for inspection. |
| Execution start | Snapshot the invocation before dispatch, including mutable arguments and environment. Reuse its idempotency key so recovery addresses the same execution even if the caller edits the request. |
| Ordinary byte writes and repeatable lifecycle operations | Repeating the operation is safe for its intended state. The TypeScript client snapshots uploaded bytes and rejects redirects, which could change the operation or origin. |

If cancellation precedes dispatch, including during capability discovery, there is no start to recover. After an ambiguous start, replay its original key under a fresh, bounded cleanup deadline. Confirm both sandbox and execution identities, send one cancellation request and poll a running acknowledgement within the remaining time. Confirmation requires a recognized terminal outcome. An inconclusive recovery preserves the key and any known identity for the caller. ## Execution outcomes

A command killed for exceeding its memory limit can report exit code 137. Go's outcome sentinels give the recorded termination reason precedence. Only an ordinary exit with a nonzero code matches the ordinary program failure sentinel. A timeout can describe the command or the sandbox lifetime. Callers can inspect sandbox state to distinguish their effects. Stream completion returns the execution snapshot. Go's Exec conveniences also return the classified error with retained output, while native TypeScript exposes a discriminated outcome.

Store future wire reason strings so an old client can report what it received. TypeScript maps them to an unknown outcome while preserving the original string. Failure handling uses structured codes and status. An adapter receiving HTTP 401 preserves the authentication failure even when a proxy sends a contradictory body code or plain text. [Go errors](../sdk.md#errors) · [TypeScript SDK](../sdk-typescript.md)

## Wire representation

Distinguish omitted, null and zero fields where the server gives them different meanings. Go request pointers allow an explicit zero. The server can omit newer controls, PID or cwd on older responses, and lists omit retained output. TypeScript keeps these response properties optional. File listings report immediate children and describe symlinks themselves. Required metadata includes valid zero IDs and mode values, so the Go decoder checks field presence before using the values. When Python decodes a file entry, an omitted owner, group or link target becomes None. An explicit JSON null for one of those fields is a protocol error. Go timestamps encode zero as null and normalize populated values to UTC.

The sandbox owns its base environment. Per-execution additions override matching names for one command. Environment values and one-shot stdin can contain credentials and stay out of execution metadata. Stdin sends up to 1 MiB of UTF-8 followed by EOF. An omitted cwd selects the image default. A bad cwd should cost one execution. The guest wrapper reports exit 126 on stderr so callers can distinguish it from a missing executable. Lifetime replacement, extension and the managed execution deadline have different effects even when all three are expressed as durations. ## Event delivery

The consumer sees events in ID order. Reconnect from the last delivered ID and discard older or duplicate IDs. A connection can carry valid output and still fail before the terminal frame, so reconnects draw from a cumulative budget across the whole observation. Live delivery, replay and the terminal snapshot draw from the same retained output. At the shared stdout/stderr byte limit the daemon retains the prefix of the final chunk that fits on a UTF-8 boundary. The event-count limit can also trigger truncation before the byte budget is exhausted. The daemon emits a single truncation marker and the command continues. Callers can recover exactly the retained prefix by replaying from the beginning. [HTTP output limits](../api.md#limits)

The terminal frame includes up to 1 MiB of command metadata and 1 MiB of retained output. JSON escaping can expand each control byte into six characters. This accounts for roughly 12 MiB before the remaining fields. Go allows up to 16 MiB per SSE line and grows its buffer on demand. TypeScript bounds decoded lines and frames, preserves multiline data, and handles UTF-8 characters and line endings split across reads. It accepts a valid final frame without a trailing blank line. Malformed data at EOF can be a cut-off frame and can be replayed from the last delivered event. A malformed explicitly delimited frame is a protocol error. The Go parser requires an event name for data-bearing blocks so the callback can identify their purpose.

A callback failure reports the original application error and closes observation. It must never trigger transport retries or remote cancellation, even if the callback throws a retryable SDK error. The TypeScript iterator owns a controller so returning from it interrupts a pending read. Explicit abort can initiate remote cleanup while a consumer is idle or awaiting a callback. The caller can request local-only cancellation. [Streaming contract](../sdk.md#streaming) · [TypeScript SDK](../sdk-typescript.md)

## Background observation

The E2B adapters implement the pinned 2.64.0 source contract. A handle observes an immutable execution. PID lookup selects the newest retained managed incarnation and returns its execution and event watermark atomically. A new observer receives only output following that watermark. An already-completed attachment provides the exit outcome and an empty output suffix. A malformed start may still establish an execution ID useful for recovery. Only a confirmed guest PID can establish a handle.

Command attachment leaves sandbox lifetime and the existing remote deadline intact. Sandbox-level connect can extend lifetime. Observation has a separate monotonic deadline that includes discovery and start retries. The Python adapter rounds positive sub-millisecond values up to one millisecond and uses the reference Python rounding rule for other ties. TypeScript observes immediately, caches even a callback rejection with an undefined value, and permits disconnect from inside a callback. Waiting for that callback while disconnecting would deadlock. Disconnect only closes observation. Sandbox deletion must still confirm removal when the stored state already says killed. The Python adapter disambiguates a missing command and a missing sandbox with a read that leaves lifetime alone. [Background command contract](../e2b-background-commands.md)

## Python socket ownership

Cancellation can race with a pooled connection being lent to another operation. Capture the socket for the current exchange before http.client clears it for a closing response. Removing a cancellation or deadline callback waits for an in-progress shutdown before returning the socket to the pool. If the idle socket probe fails, including when select cannot examine a high file descriptor, discard the connection. A connection worker performs only the connect operation so a canceled caller cannot send a request after it returns. [Python transport](../../sandbox-python/src/execlet/_transport.py)

## Verification

SDK acceptance uses a real daemon and Docker because a successful HTTP response alone cannot establish whether a process stopped or a filesystem changed. A proxy can drop an acknowledgement after the operation succeeds. A direct state read can then establish the remote outcome, and counting request arrivals reveals unintended retries even while an earlier response is still open.

The stream checks split reads at byte boundaries because TCP can coalesce separate writes. Recording small payloads verbatim and large payloads by length and hash makes replay differences verifiable without duplicating multi-megabyte logs. Browser smoke tests use the packaged client with Web APIs alone so accidental Node dependencies surface during import. The Python adapter’s one-millisecond deadline conversion uses deterministic native calls because loopback timing would make the conversion check unreliable.
