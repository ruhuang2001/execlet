# 0005. Workspace testing over MCP

Accepted. The developer’s MCP client edits the host repository and asks a sandbox to execute its tests. The host remains the source of file changes. Sync, test, edit, sync and retest work against a single sandbox until it is destroyed or expires.

## Transport and authority

`sandboxctl mcp` uses the official Go MCP SDK v1.8.0. Its stdio transport handles protocol discovery, negotiation, tool schemas and structured responses across supported protocol versions. Standard output belongs to the protocol and diagnostics use standard error. The MCP dependency and its schema and transport dependencies enter the CLI build. The daemon and public Go SDK have no MCP imports. All daemon operations use the public Go client.

Startup flags identify the host workspace and allowed images. The CLI writes a mode-0600 ownership receipt when it creates a sandbox. The receipt holds a fingerprint of the canonical host workspace, daemon endpoint, credential and allowed image and network sets. A restarted stdio process with the same authority can resume the sandbox before expiry. Sync and destroy lock the receipt across processes. If recording ownership fails, creation removes the container. The server reconciles receipts at startup and once a minute. A confirmed expired or destroyed sandbox loses its receipt and manifest. Creating a sandbox explicitly requests the offline network. Additional network modes require a startup flag and remain subject to daemon policy. The prebuilt example image supplies test dependencies while disconnected. Tools renew active sandboxes by the configured TTL. Destroy acts directly so paused sandboxes can also be removed.

## Tools and state

Clients that display only MCP text receive execution output and file contents there as well as in the structured result.

The eight tools create and destroy sandboxes, sync workspaces, start, inspect and cancel executions, and read or write guest text files. The client can supply an idempotency key when starting work. The CLI watches execution SSE events. After 60 seconds of observation an active command returns its ID. The execution stays available for inspection and cancellation. MCP requests tail retention when starting a command. After output exceeds the shared 1 MiB budget, the daemon keeps recent output, including the terminal diagnostic. The default result contains the last 64 KiB of each retained stream. Each stream reports the absolute byte position of the first returned byte and its next cursor. Pass `next_stdout_offset` and `next_stderr_offset` as `stdout_offset` and `stderr_offset` on the next request. These cursors track independently growing streams. A request behind the retained window returns the oldest available bytes and `output_lost: true`. The shared `offset` input remains available for paging a fixed snapshot.

Sync reads regular files through a rooted directory handle. When the workspace is itself the top level of a Git repository, `git ls-files --cached --others --exclude-standard` selects tracked files and eligible untracked files using Git’s own ignore rules; a directory nested inside another repository is not a workspace repository. Otherwise, or when Git is unavailable, the root .gitignore supports basename and rooted patterns, directory suffixes, negation within traversed directories and double-star path components. Every mode skips symlinks, special files, .git, .venv, node_modules and .env.

The CLI hashes each file and prepares private temporary tar archives before modifying the guest. It splits batches at the archive member, payload and path limits. Each file must fit in one batch. The manifest records pending paths before upload and atomically replaces them with confirmed versions after all batches succeed. Sync creates parent directories as the guest user, and archive upload assigns file ownership to the image user. Incremental sync removes previously uploaded host files that have disappeared. Reset uploads into a sibling directory and swaps it into place, so the dedicated guest workspace keeps its previous contents when an upload fails and is still replaced after local manifest corruption. Sandbox edits stay local to the sandbox. Destroy purges the sandbox from the daemon listing and removes its local state.


## Acceptance

The official SDK command transport drives the compiled CLI against a real daemon and Docker. The transcript includes the failing and passing test in a temporary checkout of the project’s Python SDK, a local source edit, file deletion and exclusion checks, file metadata, output paging, deadline renewal, an offline policy rejection and confirmed container cleanup. Additional cases sync full pinned checkouts of jsonschema-go and the official MCP Go SDK, check the guest copy by SHA-256, cross the 1 MiB output cap, and verify that unsuccessful archive preflights leave the guest unchanged.
